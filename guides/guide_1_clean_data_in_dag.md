# Гайд 1. Как встроить функцию очистки данных в существующий DAG

Время прохождения: 25 минут

Представьте сервис проката велосипедов. Каждый день он получает записи о поездках: номер, станцию и длительность. DAG уже выполняет три действия по порядку: получает записи, приводит названия станций к одному виду и считает сводку. Но в выгрузке иногда нет длительности, а одна и та же поездка встречается дважды. Если сразу считать сводку, результат окажется неверным.

Добавим очистку между преобразованием и расчётом. Вы напишете отдельную функцию для работы с таблицей, подключите её к задаче Airflow и проверите, какие записи дошли до итоговой сводки.

Сейчас граф такой:

```text
load_rides → transform_rides → save_summary
```

После изменения он станет таким:

```text
load_rides → transform_rides → clean_rides → save_summary
```

## Шаг 1. Разделим роли DAG и функции

DAG отвечает за порядок: когда получать записи, когда очищать их и после какого шага считать сводку. Сами правила очистки — содержательная работа с данными. Поместим их в отдельную функцию `clean_data()`, которой не нужен Airflow. Тогда её можно будет вызвать с любым подходящим `DataFrame`, например в ноутбуке или при проверке кода.

Для этого понадобятся два файла:

```text
dags/
├── bike_rides_processing.py  # функции работы с поездками
└── bike_rides_etl.py         # задачи Airflow и их порядок
```

Записей у нас четыре, поэтому между задачами передадим короткие списки через XCom. Это механизм Airflow для обмена небольшими значениями между задачами. Список, который функция возвращает через `return`, `PythonOperator` автоматически сохранит под ключом `return_value`. Следующая задача запросит это значение по имени предыдущей задачи. Большую таблицу таким способом передавать не следует: для неё понадобится отдельное хранилище.

## Шаг 2. Посмотрим на записи и напишем очистку

Сначала заглянем в существующую задачу `transform_rides`. В её функции каждая запись проходит через эти строки:

```python
updated = ride.copy()
updated["station"] = updated["station"].strip().lower()
```

`ride.copy()` создаёт копию записи. Метод `strip()` убирает пробелы по краям названия станции, а `lower()` приводит буквы к нижнему регистру. Другие поля функция не меняет. Полный код `transform_rides` увидим ниже, а сейчас посмотрим, какие записи она получает.

Входной список выглядит так:

```python
[
    {"ride_id": 501, "station": "  Центр ", "duration_min": 12},
    {"ride_id": 502, "station": "Парк", "duration_min": None},
    {"ride_id": 501, "station": "  Центр ", "duration_min": 12},
    {"ride_id": 503, "station": " Вокзал ", "duration_min": 25},
]
```

У поездки `502` длительность равна `None` — значение не пришло. Поездка `501` записана дважды. Мы только что увидели, что `transform_rides` меняет названия станций. Значит, пропуск и повтор останутся после этого шага — для них нужна отдельная очистка.

В ноутбуке можно было бы один раз вызвать методы `dropna()` и `drop_duplicates()` прямо для переменной с таблицей. Нам нужна функция с явным входом и выходом. Добавим её в `bike_rides_processing.py`:

```python
import pandas as pd


def clean_data(df: pd.DataFrame, required_columns, duplicate_columns) -> pd.DataFrame:
    # Копируем таблицу, чтобы не менять входной DataFrame.
    cleaned = df.copy()
    # Удаляем строки с пропуском хотя бы в одном обязательном столбце.
    cleaned = cleaned.dropna(subset=required_columns)
    # Для повторного номера поездки оставляем первую запись.
    cleaned = cleaned.drop_duplicates(subset=duplicate_columns)
    # Перенумеровываем строки после удаления.
    return cleaned.reset_index(drop=True)
```

Разберём эту функцию по действиям. `df.copy()` создаёт копию, поэтому вызов не меняет переданную таблицу. `dropna(subset=required_columns)` удаляет строку, если пропуск есть хотя бы в одном из перечисленных столбцов. Здесь мы передадим `ride_id` и `duration_min`: без номера нельзя распознать поездку, а без длительности нельзя посчитать минуты.

Затем `drop_duplicates(subset=duplicate_columns)` сравнивает значения в указанных столбцах. Мы передадим `ride_id`, поэтому из двух записей поездки `501` останется первая. `reset_index(drop=True)` перенумерует строки после удаления; `drop=True` не добавит прежние номера отдельным столбцом. Функция получает и возвращает `DataFrame`, не читает файлы и ничего не знает об Airflow.

Правило «оставить первую запись» подходит для этих повторяющихся строк. Если записи с одним `ride_id` могут различаться, сначала потребуется решить, какую из них считать верной.

## Шаг 3. Соединим функцию с передачей данных между задачами

`clean_data()` ожидает таблицу. Но `transform_rides` возвращает короткий список словарей, который попадает в XCom. Напишем функцию `clean_rides()`: она получит список, превратит его в `DataFrame`, вызовет готовую очистку и вернёт результат обратно как список.

```python
def clean_rides(ti):
    # Получаем короткий список записей из предыдущей задачи.
    rides = ti.xcom_pull(task_ids="transform_rides")
    # Превращаем список словарей в таблицу для функции clean_data.
    data = pd.DataFrame(rides)
    cleaned = clean_data(
        data,
        required_columns=["ride_id", "duration_min"],
        duplicate_columns=["ride_id"],
    )

    print(f"Поездок до очистки: {len(data)}")
    print(f"Поездок после очистки: {len(cleaned)}")
    # Возвращаем небольшой список, который Airflow сможет передать дальше.
    return cleaned.to_dict(orient="records")
```

Здесь `ti` — экземпляр выполняемой задачи. Вызов `ti.xcom_pull(task_ids="transform_rides")` берёт значение, которое вернула именно задача `transform_rides`. Ключ мы не указали, поэтому Airflow использует стандартный `return_value`. В нём находится список из четырёх словарей.

После `pd.DataFrame(rides)` словари превращаются в строки таблицы, а их ключи — в названия столбцов. Затем `clean_data()` получает таблицу и два списка правил. Из четырёх строк остаются две. Вызов `to_dict(orient="records")` превращает результат обратно в список словарей: один словарь соответствует одной строке. Именно этот короткий список `PythonOperator` положит в XCom для следующей задачи.

Мы не передаём `DataFrame` через XCom. Он нужен внутри `clean_rides()` для обработки; между задачами в этом примере перемещается только небольшой список записей.

## Шаг 4. Добавим задачу в существующий граф

Функция `clean_rides()` написана, но Airflow не выполнит её, пока мы не создадим задачу в `bike_rides_etl.py`:

```python
# Новый оператор вызывает обёртку, которая передаёт данные в clean_data.
clean_task = PythonOperator(
    task_id="clean_rides",
    python_callable=clean_rides,
    dag=dag,
)
```

`task_id` — имя, по которому задача видна в Airflow и по которому другие задачи находят её результат в XCom. `python_callable` — функция, которую оператор вызовет при запуске. В самом `PythonOperator` нет ни `dropna()`, ни других правил очистки.

Раньше после `transform_task` сразу выполнялась `save_task`. Изменим только связь между задачами:

```python
load_task >> transform_task >> clean_task >> save_task
```

Стрелка `>>` говорит Airflow, что следующая задача должна дождаться успешного завершения предыдущей. Она не передаёт данные: записи переходят между задачами через `return` и `ti.xcom_pull()`. Теперь `save_summary` запросит список у `clean_rides`, а не у `transform_rides`.

## Шаг 5. Соберём полный вариант

Посмотрим на оба файла целиком. В первом находятся функции, которые получают и обрабатывают записи. Во втором — настройки DAG, четыре задачи и порядок их выполнения.

Файл `dags/bike_rides_processing.py`:

```python
import pandas as pd


def load_rides():
    # Возвращаем четыре записи; PythonOperator передаст список через XCom.
    return [
        {"ride_id": 501, "station": "  Центр ", "duration_min": 12},
        {"ride_id": 502, "station": "Парк", "duration_min": None},
        {"ride_id": 501, "station": "  Центр ", "duration_min": 12},
        {"ride_id": 503, "station": " Вокзал ", "duration_min": 25},
    ]


def transform_rides(ti):
    # Получаем список, который вернула задача load_rides.
    rides = ti.xcom_pull(task_ids="load_rides")
    transformed = []

    for ride in rides:
        # Копируем запись, чтобы не менять исходный словарь.
        updated = ride.copy()
        # Убираем пробелы по краям и приводим название к нижнему регистру.
        updated["station"] = updated["station"].strip().lower()
        transformed.append(updated)

    # Airflow сохранит новый список в XCom под ключом return_value.
    return transformed


def clean_data(df: pd.DataFrame, required_columns, duplicate_columns) -> pd.DataFrame:
    # Копируем таблицу, чтобы не менять входной DataFrame.
    cleaned = df.copy()
    # Удаляем строки с пропуском хотя бы в одном обязательном столбце.
    cleaned = cleaned.dropna(subset=required_columns)
    # Для повторного номера поездки оставляем первую запись.
    cleaned = cleaned.drop_duplicates(subset=duplicate_columns)
    # Перенумеровываем строки после удаления.
    return cleaned.reset_index(drop=True)


def clean_rides(ti):
    # Получаем короткий список записей из предыдущей задачи.
    rides = ti.xcom_pull(task_ids="transform_rides")
    # Превращаем список словарей в таблицу для функции clean_data.
    data = pd.DataFrame(rides)
    cleaned = clean_data(
        data,
        required_columns=["ride_id", "duration_min"],
        duplicate_columns=["ride_id"],
    )

    print(f"Поездок до очистки: {len(data)}")
    print(f"Поездок после очистки: {len(cleaned)}")
    # Возвращаем небольшой список, который Airflow сможет передать дальше.
    return cleaned.to_dict(orient="records")


def save_summary(ti):
    # Получаем только те поездки, которые прошли очистку.
    rides = ti.xcom_pull(task_ids="clean_rides")
    # Считаем поездки и их общую длительность.
    summary = {
        "rides_count": len(rides),
        "total_minutes": int(sum(ride["duration_min"] for ride in rides)),
    }
    print(summary)
    # Сводка также сохранится в XCom под ключом return_value.
    return summary
```

Файл `dags/bike_rides_etl.py`:

```python
from datetime import datetime, timezone

from airflow import DAG
from airflow.operators.python import PythonOperator

# Функции обработки лежат отдельно от описания DAG.
from bike_rides_processing import (
    clean_rides,
    load_rides,
    save_summary,
    transform_rides,
)


# Создаём DAG для ручного запуска.
dag = DAG(
    dag_id="bike_rides_etl",
    description="Подготовка данных о поездках на велосипедах",
    start_date=datetime(2026, 9, 1, tzinfo=timezone.utc),
    schedule_interval=None,
    catchup=False,
)

# Каждая задача вызывает одну функцию из файла обработки.
load_task = PythonOperator(
    task_id="load_rides",
    python_callable=load_rides,
    dag=dag,
)

transform_task = PythonOperator(
    task_id="transform_rides",
    python_callable=transform_rides,
    dag=dag,
)

# Новый оператор вызывает обёртку, которая передаёт данные в clean_data.
clean_task = PythonOperator(
    task_id="clean_rides",
    python_callable=clean_rides,
    dag=dag,
)

save_task = PythonOperator(
    task_id="save_summary",
    python_callable=save_summary,
    dag=dag,
)

# Очистка выполняется после преобразования и до расчёта сводки.
load_task >> transform_task >> clean_task >> save_task
```

В `load_rides()` исходные записи заданы прямо в функции, поэтому каждый запуск получает те же четыре записи. Это позволяет проследить изменение данных после каждой задачи. Задача `transform_rides` возвращает новый список с приведёнными к одному виду названиями станций; исходные словари остаются без изменений.

В последней функции `save_summary()` выражение `sum(ride["duration_min"] for ride in rides)` складывает длительности только тех поездок, которые дошли после очистки. `len(rides)` считает их количество. `int(...)` превращает полученное числовое значение в целое число минут: после создания `DataFrame` длительности могут стать числами вида `12.0` и `25.0`. Функция выводит сводку в журнал и возвращает её; Airflow сохранит возвращённый небольшой словарь в XCom.

## Шаг 6. Запустим обновлённый DAG и проверим результат

После сохранения файлов откройте список DAG в Airflow и найдите `bike_rides_etl`. Откройте граф: между `transform_rides` и `save_summary` должна стоять задача `clean_rides`. Если новой задачи пока нет, дождитесь обновления DAG и снова откройте страницу.

Запустите DAG вручную и откройте **новый запуск**. В нём Airflow создаст новые экземпляры всех четырёх задач, поэтому загрузка и преобразование тоже выполнятся снова. Задачи старого завершённого запуска сохранят свои статусы: изменение кода не перезапускает их автоматически.

Сначала откройте журнал задачи `clean_rides`. В нём должны быть строки:

```text
Поездок до очистки: 4
Поездок после очистки: 2
```

Затем откройте XCom этой же задачи и найдите `return_value`. В списке должны остаться поездки `501` и `503` со станциями `центр` и `вокзал`. Значения длительности могут отображаться как `12.0` и `25.0`: при создании таблицы столбец с пропуском становится числовым столбцом с дробным типом. Поездка `502` исчезла из-за пропуска, а вторая запись поездки `501` — из-за повторного номера.

Наконец, откройте журнал `save_summary`. Ожидаемая сводка:

```text
{'rides_count': 2, 'total_minutes': 37}
```

Число `37` — сумма длительностей двух оставшихся поездок: `12 + 25`. Если задачи завершились успешно, но сводка отличается, сначала посмотрите `return_value` задачи `clean_rides`: там виден точный список, который получил расчёт.
